Add github_issue_comment MCP tool

Expose issue commenting as an MCP tool, backed by the existing
`CommentsMixin.add_comment` — no library change was needed.

The body is taken inline, which is the point of the tool: the skills currently
write a temporary file with a `cat > /tmp/... <<EOF` heredoc just to hand
multi-line Markdown to `gh issue comment --body-file`. A test covers
multi-line pass-through so that stays true.

The swallowed-failure sentinel here differs from the issue tools': an empty
`CommentData` carries `id == 0`, not `number == 0`, so the check is on
`comment["id"]`. `add_comment` already raises ValueError on an empty body, so
the tool does not re-validate it and lets the outer `except Exception` render
it.

Adds five tests to tests/github_operations/test_github_write_tools_issues.py
alongside the github_issue_create tests, plus a vulture_whitelist entry for
the tool.
