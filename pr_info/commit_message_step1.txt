Add create_issue assignees and stop get_available_labels swallowing errors

Add an optional assignees parameter to IssueManager.create_issue. Title,
body, labels and assignees are now collected into a kwargs dict so that
labels and assignees are only passed to Repository.create_issue when they
are set, keeping the no-labels call identical to the previous one.

Remove the @_handle_github_errors(default_return=[]) decorator from
get_available_labels and raise ValueError when the repository cannot be
accessed. An empty list previously meant either "the repository has no
labels" or "a swallowed 404/422/5xx", which would have made the upcoming
label validation report an API outage as an unknown-label typo. Non-auth
GithubExceptions now propagate; 401/403 already did.

Both changes are prerequisites for the github_issue_create tool.
