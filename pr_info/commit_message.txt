fix(server): restore single-line import to satisfy isort in CI

The isort CI job failed on src/mcp_workspace/server.py:

    isort --version && isort --check --profile=black --float-to-top src tests
    ERROR: src/mcp_workspace/server.py Imports are incorrectly sorted
           and/or formatted.

A single-name import had been rewritten into a parenthesized multi-line form:

    from mcp_workspace.server_reference_tools import (
        set_reference_projects,
    )

CI's isort normalizes a "from ... import <single name>" statement that fits
within line_length = 88 (this one is ~71 characters) back onto one line without
parentheses, so the file no longer matched isort's canonical output. Black
alone cannot repair this: its magic trailing comma preserves the exploded form
once the comma exists.

Collapse the import back to the single-line form. This restores the file
byte-for-byte to its origin/main state, where the same CI step passes --
"git diff origin/main -- src/mcp_workspace/server.py" is now empty.

The change is out of scope for the issue #268 work: pr_info/steps/summary.md
lists server.py under "Unchanged (deliberately)", and the stray reformatting was
swept in by 6bbe609 ("docs(pr_info): fold step 4 docs into step 3"), a
documentation-only commit. No feature work depends on it, and no other source or
test file is affected. The surrounding server_reference_tools statements (the
parenthesized get_reference_project_path / get_reference_repo_url block, whose
two names exceed the line limit, and the aliased register import) were already
in isort's expected form.

Verified: black --check, pylint, mypy --strict and the unit test suite (1775
passed, 1 skipped) are all clean.

NOTE for future work on this branch: the isort installed in the local dev
environment disagrees with CI on this construct and actively rewrites the
single-line import back into the parenthesized form. This was confirmed
empirically here -- running the local formatter re-broke the file, and
"git diff origin/main" then showed the parentheses returning. Do NOT run
tools/format_all.sh or run_format_code against this file expecting a fix; that
is how earlier attempts at this fix were lost. Verify instead with the CI
invocation itself, or by confirming that
"git diff origin/main -- src/mcp_workspace/server.py" is empty.
