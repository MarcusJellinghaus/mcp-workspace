Add perm_write probe to verify_github

Append a seventh probe key, perm_write, to _PROBE_KEYS. It reports
repository write access from repo.permissions.push as one coarse boolean
rather than synthesising five per-permission write rows the API cannot
attribute.

- New _probe_write builder: it reads a cached attribute, so it gets its
  own small function instead of going through _run_probe and
  _classify_permission_response, which are HTTP-status classifiers.
- push is tested by identity (is True / is False); anything else,
  including an unpopulated None, maps to "not checked". A failing
  permissions lookup is caught and reported as "not checked" with the
  exception text.
- severity="warning", so a failure does not flip overall_ok.
- Being in _PROBE_KEYS, it inherits the not-accessible placeholder path
  and the key-ordering guarantee for free.

Docstrings and comments that said "six read probes" / "6 placeholder
rows" are updated in _permission_probes.py, verification.py and both
test modules; the placeholder tests are renamed to drop the count.
