Suppress DOC502 for propagated exceptions in two docstrings

The ruff-docstrings CI job failed with two DOC502
(docstring-extraneous-exception) violations. DOC502 flags any exception
listed in a Raises: section that is not raised by an explicit raise
statement in the function's own body, and both documented exceptions
propagate from callees instead:

- labels_mixin.get_available_labels documents GithubException, which now
  surfaces from _get_repository()/repo.get_labels() since the
  @_handle_github_errors(default_return=[]) decorator was removed so an
  API failure can no longer be flattened into [].
- server._check_labels documents that a failed get_available_labels()
  lookup is deliberately not caught; its body contains no raise at all.

Both entries encode load-bearing contract decisions, so they are kept and
suppressed with a trailing "# noqa: DOC502  # <reason>" on the closing
docstring quotes, matching the existing convention used in 15 places
across src/ (labels_mixin.py, issues/manager.py, comments_mixin.py).
Per-file-ignores were avoided because they would blanket-disable DOC502
for every other docstring in these two modules.

Docstring annotations only; no behavioural or test changes.
